# 追蹤主角：踩過的坑

## 偵測
- 骨架模型（PoseLandmarker）一定用 **IMAGE 模式**。VIDEO 模式會黏住先追到的人，主角常被漏掉（沈伯洋那支一開始 115 格只抓到 31 格）
- 全畫面偵測常漏抓主角，所以每格再對主角附近裁一條窄框重找：寬 2.2×肩寬、高 5×肩寬，左右補黑邊，`numPoses=1`，旁邊的人進不來
- 臉部模型看的是放大後的頭部；臉要落在主角骨架頭部附近（距離 < 0.45×肩寬、臉寬 0.22～1.1×肩寬）才採用，避免抓到背景海報或旁人的臉
- 轉頭角度限制在 ±85°、俯仰 ±60°，否則會出現 −133° 這類怪值

## 認人
- 依據：位置、身形（肩寬）、衣服顏色特徵（上衣加褲子的平均顏色，`sigDist`）
- 本人顏色差距通常 < 0.1，旁人 > 0.29
- 短暫跟丟（8 格內）只在原位附近找；跟丟超過 8 格改用顏色在全畫面找回來
- **光線變化**：蔣萬安那支後段光線變了，本人顏色差距漂到 0.24～0.31，超過門檻 0.25 被當成別人，跟丟 5 秒。現在的規則：位置幾乎沒動（距離 < 0.4×肩寬）時顏色門檻放寬到 0.34；顏色記憶在差距 < 0.3 時慢慢跟著更新
- 跟丟時鏡頭停在原地等他回來，不要亂跳

## 剪輯面
- 主角突然放大成特寫、或切到別人特寫的鏡頭，最好直接剪掉，比調程式有效
- 影片開頭幾格要能抓到主角，`lock=x,y` 才會生效

## 除錯方法
瀏覽器開 `http://localhost:8830/?src=input/xxx.mp4&name=x&lock=x,y`，等模型載入後：
```js
const H=HUD, v=H.video, S=H.S;
const seek=t=>new Promise(r=>{v.onseeked=()=>r();v.currentTime=t;});
for (let t=20; t<29; t+=0.5){ await seek(t); H.detect();
  console.log(t, S.lost, [...S.near,...S.people].map(p=>Math.round(p.head.x)+'/cd'+H.sigDist(p.sig,S.refSig).toFixed(2)).join(' ')); }
```
看是「根本沒偵測到人」還是「有偵測到但被認人規則擋掉」，兩者修法不同。

## 輸出
- 即時錄影只有 6.7fps，所以改成逐格：跳到該格 → 偵測 → 畫面 → 存 JPEG → 傳給 server.py，最後 ffmpeg 合成 30fps 並接回原聲
- 影片先整支讀進記憶體（blob）再跳轉，否則每次跳轉都很慢
- Claude 瀏覽器面板收起來時會被降速，背景輸出一律用 headless Chrome（`scripts/render.sh`）
- 輸出途中伺服器若被關掉，Chrome 會一格都傳不出去也不會報錯；腳本會自己檢查並重開伺服器
